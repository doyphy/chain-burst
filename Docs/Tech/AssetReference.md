# 에셋 참조 규칙

> 멤버 변수로 다른 에셋/오브젝트를 참조할 때 하드/약한/소프트 중 무엇을 쓸지 결정하는 규칙.

상황에 따라 참조 방식을 구분한다:
| 상황 | 참조 방식 |
|---|---|
| 기본 (강하게 묶이거나 연관된 참조) | **하드 참조** (`TObjectPtr`) |
| 생명 주기가 다르거나 소유하지 않는 캐싱용 | **약한 참조** (`TWeakObjectPtr`) |
| 메모리 부담이 크거나 로드가 부담되어 최적화가 더 중요한 무거운 에셋 | **소프트 참조** (`TSoftObjectPtr` / `TSoftClassPtr`) |

**기본은 하드 참조.** 강하게 연관·묶여 있으면 하드 참조한다.

**캐싱용이라고 무조건 약한 참조가 아니다.** 생명 주기가 같으면(예: 캐릭터와 그 컴포넌트) 강하게 묶여 있는 것이므로 캐싱용 멤버도 하드 참조로 둬도 문제없다. 약한 참조는 **생명 주기가 다르거나 소유하지 않아 댕글링 위험이 있는** 캐싱에만 사용한다.

**무조건 소프트 참조가 정답은 아니다.** 소프트 참조는 로드 타이밍 문제·로드 지연·복잡한 로직을 동반하므로, 기본적으로 하드 참조로 가고, 메모리를 많이 차지하거나 로드가 부담되어 최적화 이득이 그 비용보다 크다고 판단될 때만 소프트 참조를 쓴다.

**중첩 소프트 참조(중첩 비동기 로드)를 피한다.** A가 B를 소프트 참조하고 B가 다시 C를 소프트 참조하면, 완료 신호 전파·타이밍이 복잡해진다. **비동기 경계는 한 곳에만 둔다** — 바깥에서 컨테이너(예: 로드아웃)를 소프트 참조로 비동기 로드하고, 그 **내부 에셋은 전부 하드 참조**로 두면 컨테이너 로드 한 번에 내용물이 함께 resolve된다. 대표 사례: 캐릭터→로드아웃(soft) / 로드아웃 내부(hard) → [Loadout.md](Loadout.md).

**소프트 참조 비동기 로드는 `UCBAssetManager`를 사용한다:**
- `UCBAssetManager::LoadAssetAsync<AssetType>(SoftPtr, Callback)` 로 로드.
- **이미 로드되어 있는지 검사도 `UCBAssetManager`가 내부에서 처리**하므로, 호출하는 쪽에서 따로 로드 여부를 확인할 필요 없다.
- 비동기 로드와 관련해 추가 기능이 필요하면 `UCBAssetManager`에서 수정·추가한다. (로드 로직을 호출부에 흩뿌리지 않음)
