# 보스 구역 (`ACBBossArena`)

> 게임플레이 레벨의 보스 구역. **세션의 모든 플레이어가 구역에 들어오면 5초 뒤 보스가 나타나고 입구가 막힌다.** 보스의 최대 체력과 최대 기절 게이지는 인원만큼 곱해진다. 다 들어오지 않았으면 시작하지 않고, 들어와 있는 플레이어 화면에 "다른 플레이어 대기 중"을 띄운다. 전원이 모이면 같은 자리에 보스 등장까지 남은 시간을 센다. 보스가 나타나는 순간 모든 플레이어의 카메라가 등장 연출 카메라로 넘어가고, 보스는 등장 몽타주를 재생한다. 등장 연출이 끝나면 플레이어마다 주변에 졸개(소형 몬스터)가 소환되어 그 플레이어만 쫓고, 그 플레이어의 졸개를 다 잡으면 일정 시간 뒤 다시 소환된다. 보스를 잡으면 매치가 끝나 입구가 열리고, 보스 시체가 사라지면 전원에게 클리어 화면이 뜨며(→ [GameFlow.md](../Flow/GameFlow.md) "매치 종료"), 보스전 중에 죽은 플레이어는 구역 밖의 지정한 위치에서 부활한다. 판정은 전부 서버 권위이고, 구역 액터 자신은 복제하지 않는다.

## 흐름

```
[서버] ACBBossArena — 0.5초 주기 스캔 (스포너와 같은 폴링)
  Waiting   ─ 살아서 구역 안에 있는 플레이어 ASC 에 Status.Arena.Waiting (TagOnly)
     │          └ [각 클라] HUD 의 UCBArenaWaitingWidget 이 태그 구독 → "다른 플레이어 대기 중"
     │ 구역 안 생존 인원 == 접속 인원 전원
     ▼
  Countdown ─ 대기 태그 전부 제거
     │          + 플레이어마다 카운트다운 GE (기간 = BossAppearDelay, 부여 태그 Status.Arena.Countdown)
     │          + BossAppearDelay 1회 타이머
     │          └ [각 클라] 같은 위젯이 태그로 시작·종료, 매 틱 GE 남은 시간 → 숫자 카운트다운
     │          └ 스캔에서 한 명이라도 나가거나 죽으면 취소(타이머 해제·GE 제거) → Waiting (다시 들어오면 처음부터)
     ▼ 타이머 만료 — 인원을 한 번 더 확인 (아니면 취소)
  Fighting  ─ 보스 소환(BossSpawnPoint) + 입구 차단 액터 소환(EntranceBlockerPoint, 복제)
     │          + 등장 연출 (아래 "등장 연출")
     │          └ 보스 준비 완료 → 최대 체력·최대 기절 게이지 × 접속 인원, 체력 가득 (아래 "인원 비례 내구도")
     │          ├ 보스 사망 → 게임모드에 보스 처치 통지(매치 클리어) + 남은 졸개 사망 처리 + 입구 차단 액터 파괴 → Cleared
     │          ├ 구역 안 생존 인원 0명(전멸) → 보스·졸개 파괴 + 입구 개방 → Waiting
     │          └ 연출이 끝난 뒤 매 스캔 → 졸개 진행 (아래 "졸개")
     ▼
  Cleared   ─ 보스 시체가 사라지기를 기다림 (보스의 DespawnDelay 뒤 파괴 → 약참조가 빔)
     │          └ 사라지면 게임모드에 소멸 통지 → 전원 클리어 화면 + 스캔 중지
     ▼
  (끝)

[서버] 플레이어 사망 (ACBGameplayGameMode::Auth_HandlePlayerDeath)
  └ 보스전 중인 구역이 있으면 그 RespawnPoint 를 부활 위치로 정해 리스폰 타이머에 실음
       → RespawnDelay 뒤 RestartPlayerAtTransform (없으면 평소대로 RestartPlayer → PlayerStart)
```

## 단계 규칙

| 현재 단계 | 조건 | 결과 |
|---|---|---|
| Waiting | 구역 안 생존 인원 == 접속 인원 (1명 이상) | Countdown, 대기 태그 전부 제거, 카운트다운 GE + 타이머 (`BossAppearDelay` 가 0 이면 곧바로 Fighting) |
| Waiting | 그 외 | 구역 안 생존 플레이어에게만 대기 태그 |
| Countdown | (스캔) 한 명이라도 구역 밖·사망·리스폰 대기 | **취소** — 타이머 해제·GE 제거 → Waiting |
| Countdown | 타이머 만료 + 인원 재확인 통과 | 카운트다운 GE 제거, 보스 + 입구 차단 액터 소환 → Fighting |
| Countdown | 타이머 만료 + 인원 재확인 실패 | **취소** → Waiting |
| Fighting | 보스 사망(또는 사라짐) | 게임모드에 보스 처치 통지(매치 클리어 — 졸개 처리보다 먼저), 남은 졸개 사망 처리, 입구 개방 → Cleared. **입구는 시체가 사라질 때까지 기다리지 않는다** |
| Cleared | 보스가 사라짐(파괴되어 약참조가 빔) | 게임모드에 소멸 통지 → 클리어 화면, 스캔 중지. 처치 때 이미 없었거나 `DespawnDelay` ≤ 0(스스로 사라지지 않음 — 경고)이면 처치 순간 바로 |
| Fighting | 구역 안 생존 인원 0명 | **전멸 리셋** — 보스·졸개 파괴 + 입구 개방 → Waiting |
| Fighting | 그 외 + 등장 연출 끝남 | 졸개 진행 (아래 "졸개") |

- **보스 처치를 전멸보다 먼저 본다.** 마지막 일격과 동시에 전원이 쓰러져도 승리로 친다.
- **"전원"은 서버의 플레이어 컨트롤러 전부다.** 죽어서 리스폰을 기다리는 플레이어(폰 없음·사망)도 "밖"으로 세므로 그 사람을 기다린다. 대기 중에 누가 접속을 끊으면 남은 인원으로 바로 충족될 수 있다. 시체가 구역 안에 남아도 인원에 들어가지 않는다.
- **레벨업 정지 중에는 카운트다운도 멈춘다.** 보스 등장 타이머가 월드 타이머이고 카운트다운 GE 의 기간도 월드 시간으로 흐르므로 둘이 함께 멈췄다 함께 재개한다 (→ [LevelUp.md](LevelUp.md) "정지").

## 왜 이렇게 했나

### 폴링 — 스포너와 같은 이유

트리거 오버랩 대신 `ScanInterval`(0.5초, 코드 상수) 타이머 하나로 인원 집계·카운트다운 이탈·전멸·보스 사망·처치 뒤 보스 소멸을 모두 본다(보스 등장 시각만 예외 — 아래 "카운트다운"). 사망 후 리스폰마다 폰이 새로 생기므로(→ [GameFlow.md](../Flow/GameFlow.md)) 오버랩 상태를 폰마다 다시 맞춰야 하는데, 스캔마다 플레이어 컨트롤러에서 현재 폰을 읽으면 그 문제가 없다. 보스의 사망 델리게이트도 구독하지 않고 약참조 + `IsDead()`로 본다 — 해제 누락이 생기지 않는다 (→ [Spawner.md](Spawner.md) "왜 폴링인가").

이탈 감지가 최대 스캔 주기(0.5초)만큼 늦을 뿐이라 주기는 튜닝 대상이 아니다.

### 카운트다운 — 기간 GE + 1회 타이머

전원이 모이면 대기 문구 자리에서 보스 등장까지 남은 시간을 센다. 위젯이 "모였다"와 "얼마 남았나"를 알아야 하는데, **새 RPC·델리게이트 없이** 대기 표시와 같은 길(서버가 플레이어 ASC 에 걸고 위젯이 구독)로 보낸다.

- **태그만으로는 시간을 실을 수 없다.** 태그 하나를 더 두고 위젯이 5초를 따로 들면 WBP 와 `BossAppearDelay` 두 곳에 같은 값이 생겨, 한쪽만 고치면 숫자와 실제 등장이 어긋난다.
- 그래서 **기간 GE** 를 건다. 플레이어 ASC 는 Mixed 라 소유 클라이언트가 GE 의 기간·시작 시각까지 받고, 위젯은 `GetActiveEffectsTimeRemaining` 으로 읽기만 한다 — 버스트 게이지·스킬 쿨다운 슬롯과 같은 방식이다(→ [UI.md](../Presentation/UI.md)).
- **기간은 `Spec.SetDuration(BossAppearDelay, true)` 로 덮어쓴다.** 값이 구역 인스턴스 한 곳에만 있고, GE 에셋에 적힌 기간은 쓰이지 않는다. `bLockDuration` 이라 적용 과정의 재계산이 덮지 않는다.
- **취소는 GE 제거 한 가지다.** 태그가 떨어지면 위젯의 카운트다운이 내려가고, 동시에 대기 태그가 다시 붙어 대기 문구로 돌아간다.
- `BeginPlay` 에서 GE 가 **기간형인지·`Status.Arena.Countdown` 을 부여하는지** 확인하고, 아니면 경고 후 쓰지 않는다(표시 없이 카운트다운만 진행). 조건이 틀리면 화면만 조용히 비기 때문이다.

**보스 등장은 스캔 비교가 아니라 1회 타이머다.** 스캔으로 시각을 비교하면 숫자가 0 이 된 뒤 최대 0.5초 늦게 보스가 나온다. 카운트다운 시작 때 `BossAppearDelay` 타이머를 걸고, 취소되면 해제한다. 타이머 만료는 스캔 사이일 수 있으므로 **인원을 한 번 더 확인**하고(그 사이 나간 사람이 있으면 취소), 보스를 소환하기 전에 남은 GE 를 직접 걷어낸다 — 타이머와 GE 만료는 같은 시각이지만 처리 순서에 기대지 않는다.

### 보스는 배치가 아니라 소환

보스를 맵에 미리 두지 않고 구역이 소환한다. 런타임 생성이라 **생성 연출(로드아웃 `SpawnCueTag`)·AI 두뇌 시작·보스 바가 전부 캐릭터 쪽 기존 경로로** 돌아간다 (→ [SpawnFX.md](../Presentation/SpawnFX.md), [AI.md](AI.md), [UI.md](../Presentation/UI.md) "보스 바"). 배치형으로 두려면 등장 전까지 AI 를 잠재워 두는 상태가 새로 필요하다.

- 보스 바는 여전히 **보스의 첫 타겟 획득**(`Status.Combat.Engaged`)으로 뜬다. 최초 타겟은 퍼셉션(시야 120°·청각·피격)으로 잡으므로 **보스 화살표가 플레이어 쪽을 보게** 둔다. 등을 돌린 채 나오면 플레이어가 소리를 내거나 때리기 전까지 바가 늦게 뜬다.
- 보스 BP 의 `Always Relevant` 는 그대로 필요하다 (→ [UI.md](../Presentation/UI.md) "⚠️ 연관성").

### 인원 비례 내구도 — 보스 준비 완료에서 × 인원

플레이어가 늘면 보스가 받는 공격도 그만큼 늘어나므로, 보스의 **최대 체력과 최대 기절 게이지를 접속 인원만큼 곱한다**(1명 ×1, 2명 ×2 …). 체력은 늘어난 최대까지 채운다. 혼자일 때 값(로드아웃 데이터)이 기준이고 1명이면 아무것도 바꾸지 않는다.

```
[서버] Auth_HandleBossReady (보스 준비 완료 — 등장 어빌리티 발동 직전)
  └ Auth_ScaleBossByPlayerCount(보스 ASC)
       N = 서버의 플레이어 컨트롤러 수 (1 이하면 끝)
       MaxHealth    기본값 × N
       MaxStunGauge 기본값 × N      (기본 100 — 1인 기준)
       CurrentHealth = 늘어난 MaxHealth
```

- **보스 준비 완료에서 곱한다.** 보스 체력은 로드아웃 시작 GE(`GE_Outlaw_Hulk_Init` — Instant Override, 커브 값)가 정하는데, 이 GE 는 서버의 로드아웃 로드 콜백에서 준비 완료 직전에 적용된다(→ [Multiplayer.md](../Conventions/Multiplayer.md) "초기화 흐름"). 소환 직후(`SpawnActor` 반환)에 곱하면 로드아웃이 아직 디스크에서 읽히는 중일 때 뒤늦게 온 Override 가 덮어쓴다. 구역은 이미 이 시점에 등장 어빌리티를 발동하므로 그 앞에 한 줄 넣었다.
- **인원은 접속 인원이다.** 보스전은 접속 인원 전원이 살아서 들어와야 시작하므로 그대로 보스전 인원이다. 난입이 막혀 있어(`bAllowJoinInProgress = false` → [LevelUp.md](LevelUp.md)) 보스전 중 인원은 줄기만 한다.
- **기본값에 바로 쓴다(`SetNumericAttributeBase`).** 보스 ASC 는 보스와 함께 사라져 되돌릴 일이 없다. 기절 패시브가 게이지를 같은 방식으로 기록한다(→ [Stun.md](Stun.md)). 어트리뷰트라 Minimal 복제 모드여도 전 클라로 가고, 보스 바의 체력·기절 위젯이 이미 그 값을 읽으므로 **네트워크·UI 코드가 없다.**
- **전멸 리셋 뒤 새 보스는 그때의 인원으로 다시 곱한다.** 그 사이 누가 나갔으면 그만큼 약한 보스가 나온다.
- **최대 기절 게이지가 늘어나는 의미와 한계**는 → [Stun.md](Stun.md) "최대값 — 보스전 인원만큼" (보스 자기 스킬 적립량은 인원과 무관).

### 등장 연출 — 카메라는 구역이, 몽타주는 보스가

보스가 소환되는 순간 모든 플레이어 카메라가 등장 연출 카메라로 넘어가고, 보스는 등장 몽타주를 재생한 뒤 싸움을 시작한다. **새 네트워크 코드는 없다** — 카메라·입력은 엔진 RPC, 몽타주는 기존 GameplayCue 경로다.

```
[서버] Auth_StartBossFight — 보스 소환 직후 Auth_StartBossIntro
  ├ 모든 PC: SetViewTargetWithBlend(구역 액터 → IntroCamera) + SetCinematicMode(이동·시점 차단)
  │     원격 PC 는 엔진이 ClientSetViewTarget / ClientSetCinematicMode 로 보냄
  │   + 플레이어 ASC 에 행동 차단 GE (IntroBlockEffectClass — 공격·장착·해제·버스트·이동 계열 어빌리티)
  └ 보스 준비 완료(서버) — 구독 또는 즉시
       ├ 보스 ASC 의 Status.Combat.Intro 변경 구독  (발동보다 먼저)
       └ Event.Combat.Intro → GA_Boss_Intro
            ActivationOwnedTags: Status.Combat.Intro + Status.Combat.Staggered + Status.Combat.SuperArmor
            등장 몽타주(Action.Combat.Intro) → GameplayCue.PlayAction → 전 클라

[서버] Status.Combat.Intro 제거 (몽타주 블렌드 아웃 시작 = 어빌리티 종료)
  └ Auth_EndBossIntro — 모든 PC: 카메라를 자기 폰으로 블렌드 + 시네마틱 해제 + 차단 GE 제거
```

**카메라는 구역 액터의 컴포넌트다.** 구도는 방 구조에 달려 있으므로 화살표처럼 레벨에서 잡는다. 구역은 레벨 배치 액터라 **복제하지 않아도 모든 클라이언트에 같은 위치로 존재하고**, 이름이 안정적이라(`IsNameStableForNetworking`) RPC 로 참조를 보낼 수 있다. 그래서 서버가 "구역 액터를 봐라"라고 보내면 각 클라가 자기 쪽 구역의 `IntroCamera` 로 본다(`AActor::CalcCamera` 가 활성 카메라 컴포넌트를 찾음). 로비 카메라(`ACBLobbyCamera`)가 같은 방식으로 이미 동작한다 (→ [Lobby.md](../Flow/Lobby.md)).

**카메라 전환은 서버가 건다.** 서버가 원격 PC 의 뷰 타겟을 바꾸면 엔진이 `ClientSetViewTarget` 으로 클라이언트에 강제한다(`PlayerCameraManager.cpp`). 클라이언트가 스스로 바꾸는 방식과 달리 서버와 어긋날 여지가 없다. 이동·시점 입력은 엔진의 시네마틱 모드(`APlayerController::SetCinematicMode`)로 막는다 — 서버에서 부르면 `ClientSetCinematicMode` 로 클라이언트에 간다. 폰·HUD 표시는 건드리지 않는다.

**행동은 차단 GE 가 막는다.** 시네마틱 모드는 이동 입력(`AddMovementInput`)과 시점만 무시하므로, 그 경로를 거치지 않는 행동은 그대로 나간다.

| 어빌리티 | 시네마틱 모드로 막히나 | 이유 |
|---|---|---|
| 공격 (Basic·Skill A~E) | ✗ | 어빌리티 입력 |
| 대시 · Sprint | ✗ | 루트 모션 몽타주로 이동 (Sprint 는 전방 대시를 발동 → [Locomotion.md](Locomotion.md)) |
| 점프 | ✗ | CMC `Jump()` 를 직접 부름 |
| 버스트 · 무기 장착/해제 · 걷기 전환 | ✗ | 몽타주·상태 변경 |

그래서 연출 동안 플레이어 ASC 에 **Infinite GE + "Block Abilities with Tags" 컴포넌트**(`IntroBlockEffectClass`)를 걸고 끝날 때 `RemoveActiveGameplayEffectBySourceEffect` 로 걷는다.

- **차단 태그는 다섯 개** — `Ability.Combat.Attack`, `Ability.Combat.EquipWeapon`, `Ability.Combat.UnequipWeapon`, `Ability.Combat.Burst`, `Ability.Movement`. `AreAbilityTagsBlocked` 가 어빌리티 쪽 태그의 부모까지 펼쳐 비교하므로 부모 태그 하나로 하위가 함께 막힌다. `Ability.Combat` 전체를 막지 않는 것은 피격 반응까지 묶이기 때문이다(사망은 `bIgnoreAbilityBlocking` 이라 어차피 뚫는다). 이미 켜져 있는 패시브(버스트 게이지·적중 회복)는 차단이 새 발동만 막으므로 영향이 없고, 상태창(UI)은 두었다.
- **GE 여야 하는 이유 — 예측.** 공격은 `LocalPredicted` 라 클라이언트가 먼저 발동한다. 서버에서만 `BlockAbilitiesWithTags` 를 부르면 클라가 몽타주를 시작했다가 서버 거부로 끊긴다. 플레이어 ASC 는 Mixed 라 소유 클라이언트가 GE 를 받고, 엔진이 GE 를 활성화할 때 차단 태그를 서버·클라 양쪽에 적용한다(`FActiveGameplayEffectsContainer::AddActiveGameplayEffectGrantedTagsAndModifiers`). 버스트 위젯이 클라에서 GE 부여 태그를 읽는 것과 같은 경로라 클라는 예측 발동부터 하지 않는다.
- **연출 중 죽어 리스폰해도 따로 처리할 것이 없다.** ASC 가 PlayerState 소유라 GE 가 남아 있고(사망 정리는 `Status.Dead` GE 와 로드아웃 부여분만 걷음), 연출이 끝날 때 모든 PC 를 돌며 함께 걷는다.
- `BeginPlay` 에서 GE 가 **Infinite 인지·차단 태그가 있는지** 확인하고, 아니면 경고 후 쓰지 않는다(이동·시점만 막힘). 컴포넌트를 빠뜨리면 행동이 조용히 풀려 있기 때문이다.

**연출 길이는 몽타주 길이 하나뿐이다.** 구역은 시간을 들지 않고 보스 ASC 의 `Status.Combat.Intro` 가 빠지는 순간(어빌리티 종료 = 자기 몽타주의 블렌드 아웃 시작 → [Montage.md](Montage.md))에 카메라를 되돌린다. 기절 시간 = 기절 몽타주 길이와 같은 원칙이다 (→ [Stun.md](Stun.md)).

- **종료 구독을 발동보다 먼저 건다.** 어빌리티가 발동한 호출 안에서 곧바로 끝나도(몽타주 누락 등) 제거 이벤트를 놓치지 않는다.
- **태그가 없으면 바로 되돌린다.** 이벤트 발행 뒤에도 `Status.Combat.Intro` 가 없으면 — 발동된 어빌리티가 없거나(로드아웃 부여·트리거 누락) `ActivationOwnedTags` 에 빠졌거나 — 끝을 알릴 신호가 없어 **카메라가 묶인 채 남는다.** 그래서 경고 로그를 남기고 즉시 종료한다.
- **보스 처치·전멸 리셋도 연출을 끝낸다.** 보스가 파괴되면 태그 제거 이벤트가 오지 않으므로 두 경로가 먼저 `Auth_EndBossIntro` 를 부른다. 종료는 한 번만 처리된다(`bBossIntroActive`).
- 되돌릴 때 **폰이 없는 플레이어(리스폰 대기)는 건드리지 않는다.** 다음 빙의가 뷰 타겟을 폰으로 맞춘다.

**보스는 연출 동안 서 있다.** 등장 어빌리티가 `Status.Combat.Staggered` 를 소유해 BT 경직 분기(이동을 끊고 대기)를 그대로 탄다 — 기절과 같은 재사용이라 AI·BT 코드가 바뀌지 않는다 (→ [AI.md](AI.md) "피격 경직"). `SuperArmor` 는 연출 중 맞아도 피격 반응이 몽타주를 끊지 않게 한다(데미지는 들어감).

- **보스 바는 연출 중에 뜰 수 있다.** 두뇌는 준비 완료에 시작하므로 연출 중에도 퍼셉션이 플레이어를 발견하고 `Engaged` 가 붙는다. 등장 타이틀처럼 보여서 그대로 둔다.
- **발동 시점은 서버의 보스 준비 완료다.** 등장 어빌리티를 로드아웃이 부여하기 때문이다. 로드아웃이 이미 메모리에 있으면 `SpawnActor` 안에서 준비까지 끝나 있어 즉시 발동한다. 그 경우에도 몽타주 큐(신뢰성 없는 멀티캐스트)는 버려지지 않는다 — 서버는 채널이 없는 연결에 RPC 를 보낼 때 채널을 열고, 신뢰성 없는 멀티캐스트는 액터 첫 복제와 함께 나가도록 큐잉한다(`NetDriver.cpp` `InternalProcessRemoteFunctionPrivate`).
- 카메라는 소환 순간에 먼저 넘어가므로 **생성 연출(디졸브)부터 보인다** (→ [SpawnFX.md](../Presentation/SpawnFX.md)).
- **보스 BGM 도 같은 순간 시작한다.** 구역이 아니라 보스가 각 머신의 준비 완료에서 로드아웃 `BossMusic` 으로 레벨 BGM 을 덮어쓰고, 사망·파괴(전멸 리셋) 때 되돌린다 — 구역은 음악을 모른다 (→ [Music.md](../Presentation/Music.md)).

### 입구 — 켜고 끄지 않고 소환·파괴

입구를 막는 벽은 **클라이언트에도 충돌이 있어야** 한다. 서버에만 있으면 클라의 이동 예측이 벽을 통과했다가 서버 보정으로 튕긴다. 복제되는 액터를 소환하면 모든 머신에 충돌째로 나타나고, 파괴하면 모두에서 사라지므로 **OnRep 같은 복제 코드가 필요 없다.** 구역 액터도 복제할 필요가 없어진다.

- 복제는 BP 체크박스에 맡기지 않고 소환 직후 `SetReplicates(true)`로 켠다 — 빠뜨리면 위의 튕김이 조용히 생긴다. 초기화가 끝난 액터라도 엔진이 그 자리에서 네트워크 액터 목록에 넣는다(`AActor::SetReplicates`).
- 소환은 `AlwaysSpawn`. 벽 위치에 누가 서 있어도 소환한다 — 그래서 아래 "배치 규칙"이 필요하다.

### 대기 표시 — 복제되는 태그

서버가 이미 "누가 안에 있는가"를 매 스캔 계산하므로, 그 결과를 플레이어 ASC 의 `TagOnly` 루스 태그로 내보내고 HUD 위젯이 구독한다. UI.md 의 원칙(UI 용 RPC·복제 코드를 만들지 않음, 복제되는 신호를 UI 가 구독)과 보스 바의 `Engaged` 선례 그대로다.

- 태그가 **PlayerState 소유 ASC** 에 있어, 리스폰으로 HUD 위젯이 새로 생겨도 구독할 때 현재 상태를 바로 읽는다.
- 태그는 구역 액터가 매 스캔 "지금 안에 있는 플레이어"와 맞춘다(`Auth_UpdateWaitingTags`). 사망하면 다음 스캔에 떨어지고, 접속을 끊으면 PlayerState 와 함께 사라진다. 폰이 아니라 구역이 소유한 상태라 GameplayTags.md ③의 "폰이 사라질 때 뺀다" 대상이 아니다.
- PlayerState 갱신 주기를 30Hz 로 올려 두었으므로 표시 지연은 수십 ms 다 (→ [Multiplayer.md](../Conventions/Multiplayer.md) "복제 갱신 주기").

### 보스전 중 사망자 부활 — 사망 시점에 정한다

보스전 중 죽은 플레이어는 구역 밖의 `RespawnPoint` 에서 부활한다(입구가 막혀 있으므로 다시 들어오지 못하고 기다린다). **부활 위치는 죽은 순간 정한다.** 부활 시점(5초 뒤)에 "지금 보스전 중인가"를 물으면, 전멸 리셋 뒤에 부활하는 마지막 사망자들만 맵 시작 PlayerStart 로 가 버린다.

- `ACBGameplayGameMode::Auth_HandlePlayerDeath` 가 `Auth_FindBossFightRespawnTransform` 으로 부활 위치를 구해 리스폰 타이머 람다에 함께 싣는다. 새 멤버 변수는 없다.
- 게임모드는 구역을 **사망 시점에 레벨을 훑어(`TActorIterator`) 찾는다.** 구역이 게임모드에 등록·해제하는 방식은 해제 누락의 여지가 있고, 사망은 드문 이벤트라 훑는 비용이 무시할 만하다.
- 대기·카운트다운 중 사망은 평소대로 PlayerStart 에서 부활한다.
- 보스전 중 구역 밖에서 죽은 플레이어(이미 부활해 밖에 있던 플레이어)도 같은 부활 지점으로 간다 — "보스전 중 사망자"의 정의가 위치가 아니라 시점이라서다.

### 전멸 리셋

부활은 구역 밖이므로, 보스전 중 구역 안 생존자가 0명이 되면 아무도 다시 들어갈 수 없어 진행이 멈춘다. 그래서 그 순간 **보스를 파괴하고 입구를 열어 Waiting 으로** 되돌린다. 다시 전원이 들어오면 체력이 가득 찬 새 보스가 나온다.

- 보스는 죽은 게 아니라 사라지는 것이라 **소멸 연출 없이** 파괴된다. 보스 바는 보스 파괴(`EndPlay(Destroyed)`)에서 함께 내려간다 (→ [UI.md](../Presentation/UI.md) "표시 규칙").
- 연출이 필요해지면 리셋 지점에서 보스에 소멸 GE 를 적용하고 그 길이만큼 늦춰 파괴한다.

### 졸개 — 플레이어마다 따로, 그 플레이어만 쫓는다

등장 연출이 끝나면 구역 안 생존 플레이어마다 **주변에 졸개 `MinionsPerPlayer`(3) 마리**가 나타나 그 플레이어만 쫓는다. 그 플레이어의 졸개가 전부 죽으면 `MinionRespawnDelay` 뒤 **그 플레이어 주변에만** 다시 나온다. 판정은 보스전 스캔이 그대로 한다.

```
[서버] Auth_ScanTick — Fighting, 보스 생존, 구역 안 생존자 있음, 등장 연출 끝남
  └ Auth_UpdateMinions(구역 안 생존 플레이어)
       ① 묶음마다 죽은(IsDead)·사라진 졸개 정리. 방금 비었으면 다음 소환 = 지금 + MinionRespawnDelay
       ② 구역 안 플레이어마다
            처음 보는 플레이어 → 묶음 생성, 다음 소환 = 지금 + MinionRespawnDelay
            묶음이 비었고 시각이 됨 → 주변에 MinionsPerPlayer 마리 소환 + 각 졸개 컨트롤러에 Auth_AssignTarget(그 플레이어 폰)
```

**구역 안에 둔 이유.** 졸개에 필요한 판단 재료 — 보스전 단계, 연출 여부(`bBossIntroActive`), 구역 안 생존 플레이어(스캔이 이미 셈), 구역 박스 판정(`IsInsideArena`), 끝나는 시점(처치·전멸) — 가 전부 구역에 있다. 별도 액터·컴포넌트로 빼면 이것들을 공개하거나 다시 세야 한다.

- **연출이 끝난 뒤부터.** 연출 동안 플레이어는 행동 차단 GE 로 묶여 있어 그때 졸개가 오면 맞기만 한다.
- **첫 소환도 `MinionRespawnDelay` 뒤.** 연출이 끝나자마자 몰려오지 않게 하고, 값을 따로 두지 않으려고 재소환 지연을 같이 쓴다. 0 이면 연출이 끝난 다음 스캔에 바로 나온다.
- **사망 델리게이트를 구독하지 않는다.** 스캔에서 약참조 + `IsDead()` 로 정리한다 — 스포너·보스와 같은 이유(→ "폴링 — 스포너와 같은 이유").
- **묶음의 키는 플레이어 컨트롤러.** 리스폰으로 폰이 바뀌어도 같은 플레이어다. 접속을 끊은 플레이어의 묶음도 보스전이 끝날 때 함께 정리되도록 지우지 않는다.
- **동시 생존 상한은 따로 없다.** 인원 × `MinionsPerPlayer` 가 이미 상한이다.
- 레벨업 정지 중에는 스캔 타이머와 월드 시간이 함께 멈추므로 재소환 대기도 멈춘다.

**소환 지점 — 그 플레이어를 둘러싼 고리.** 플레이어 위치에서 `GetRandomReachablePointInRadius(MinionSpawnRadius)` 로 뽑고, 아래를 만족하는 지점만 쓴다. `MaxMinionSpawnLocationTries`(10, 코드 상수) 안에 못 찾으면 그 한 마리만 건너뛴다(스포너와 같음). 한 마리도 못 냈으면 재소환 대기부터 다시 센다 — 매 스캔 재시도로 경고가 쌓이지 않게.

| 조건 | 이유 |
|---|---|
| 그 플레이어에게서 **걸어갈 수 있는**(reachable) 지점 | 벽 너머의 끊긴 내비메시 조각 제외 |
| **구역 박스 안** | 입구 통로는 내비메시로 이어져 있어, 박스 검사가 없으면 입구 벽 너머에 나올 수 있다. 그래서 **박스가 바닥을 덮어야** 한다(지점이 바닥 높이) |
| 구역 안 **모든 플레이어**에게서 `MinionSpawnRadius` 의 **절반 밖** | 코앞에 튀어나오는 것 방지. 최소 거리를 따로 두지 않고 반경에서 유도 |

나타날 때 쫓을 플레이어를 바라보게 세우고, 높이는 보스·부활과 같은 `MakeGroundedSpawnTransform`(위치 + Yaw 버전)으로 캡슐 절반만큼 띄운다. 생성 연출은 졸개 로드아웃의 `SpawnCueTag` 로 캐릭터가 스스로 재생한다(→ [SpawnFX.md](../Presentation/SpawnFX.md)).

**그 플레이어만 쫓는다 — 지정 타겟.** AI 는 원래 퍼셉션으로 타겟을 고르므로, 그대로 두면 졸개가 ① 등 뒤에 나왔을 때 가만히 있는 플레이어를 못 알아채고(시야 120°, 정지 = 무소음) ② 다른 플레이어가 더 가깝거나 때리면 그쪽으로 가고 ③ 기둥 뒤로 숨으면 5초 뒤 놓친다. 그래서 소환 직후 컨트롤러에 `Auth_AssignTarget(플레이어 폰)` 을 건다 — 그 폰이 살아 있는 동안은 인지·점수와 무관하게 그 대상만 쫓는다(→ [AI.md](AI.md) "지정 타겟"). AI 컨트롤러는 `SpawnActor` 안(`APawn::PostInitializeComponents` 의 자동 빙의)에서 이미 붙어 있어 소환 직후 바로 지정할 수 있다.

- **주인이 죽으면 남은 졸개는 평범한 잡몹이 된다.** 지정한 폰이 죽으면 지정이 풀린 것처럼 퍼셉션으로 남은 플레이어를 노린다. 주인은 구역 밖에서 부활하므로 그 몫은 다시 소환되지 않는다(구역 안 생존 플레이어에게만 소환).
- 지정은 폰이라, 폰이 바뀌는 경우는 사망 리스폰뿐이다(무기 변경은 로비 전용 → [GameFlow.md](../Flow/GameFlow.md)). 그래서 다시 지정하는 처리가 없다.

**끝날 때.**

| 끝 | 남은 졸개 | 이유 |
|---|---|---|
| 보스 처치 | **사망 처리** — 사망 이벤트(`Event.Combat.Death`)를 보내 체력이 0 이 됐을 때와 같은 경로(사망 몽타주·사망 상태·소멸 연출·시체 정리) | 보스와 함께 쓰러지는 그림. 즉시 파괴하면 보스가 쓰러지는 순간 졸개가 연출 없이 사라진다 |
| 전멸 리셋 | **즉시 파괴** | 보스와 같은 처리. 다음 보스전은 묶음을 처음부터 다시 센다 |

- 사망 이벤트로 발동된 어빌리티가 없으면(준비 전이라 아직 부여 전·로드아웃 누락) 그 졸개는 파괴한다. 보스전이 끝난 뒤에도 졸개가 살아서 쫓아오지 않게.
- **보스 처치 때 쓰러지는 졸개의 처치 보상은 들어가지 않는다.** 구역이 졸개를 사망 처리하기 **전에** 게임모드에 보스 처치를 알리고, 매치가 끝난 게임모드는 경험치를 무시한다 — 보상으로 레벨이 올라 클리어 화면 위에 월드 정지·카드 창이 뜨지 않게 (→ [GameFlow.md](../Flow/GameFlow.md) "매치 종료"). 보스전 도중 잡은 졸개의 보상은 평소처럼 들어간다(`ExperienceReward` → [LevelUp.md](LevelUp.md)).

### 스폰 높이 — 화살표는 바닥에

보스·부활 화살표는 **바닥에 둔다.** 소환할 때 그 클래스 CDO 의 캡슐 절반 높이만큼 띄운다(`MakeGroundedSpawnTransform` — 스포너의 내비메시 지점 처리와 같음). 화살표 버전은 "바닥 위치 + Yaw" 버전을 부르며, 졸개는 내비메시 지점으로 그 버전을 직접 쓴다. 회전은 Yaw 만 쓴다. 입구 차단 액터는 캐릭터가 아니라 화살표 위치·회전을 그대로 쓰므로, BP 의 원점을 바닥 중앙 등 화살표에 맞출 자리로 잡는다.

## 레벨 배치 규칙

| 대상 | 규칙 | 이유 |
|---|---|---|
| `ArenaBounds` | 보스 방 전체를 덮는다. 입구 통로는 포함하지 않는다. **바닥면까지 덮는다** | 통로에 서 있는 사람을 "안"으로 치면 그 위에 벽이 생길 수 있음. 졸개 소환 지점(바닥 높이)도 박스 안이어야 쓰임 |
| `EntranceBlockerPoint` | **박스 바깥**, 통로 쪽 | "안"으로 판정된 플레이어 위에 벽이 생기면 밀려나는 방향이 정해지지 않아 밖으로 튕길 수 있음 |
| `BossSpawnPoint` | 바닥, **플레이어가 들어오는 쪽을 보게** | 최초 타겟은 시야 퍼셉션 — 등을 돌리면 보스 바가 늦게 뜸 |
| `RespawnPoint` | 박스 바깥의 **트인 바닥** | 광역 공격으로 여럿이 동시에 죽으면 같은 자리에 동시에 부활한다. 폰 스폰 기본값(`AdjustIfPossibleButDontSpawnIfColliding`)은 겹치면 비켜 스폰하고, 비킬 자리가 없으면 스폰을 포기한다 |

| 이름 | 기본값 | 설명 |
|---|---|---|
| `BossClass` | (비어 있음) | 소환할 보스. **비어 있으면 구역이 동작하지 않고 경고** |
| `EntranceBlockerClass` | (비어 있음) | 입구 차단 액터. 비어 있으면 입구를 막지 않고 경고 (보스전은 진행) |

| `CountdownEffectClass` | (비어 있음) | 카운트다운 표시용 기간 GE. 기간형 + `Status.Arena.Countdown` 부여가 아니면 경고 후 표시 없이 진행 |
| `IntroCameraBlendTime` | 0.5초 | 등장 연출 카메라로 들어갈 때·폰으로 돌아올 때의 블렌드. 0 이면 즉시 전환 |

| `MinionClass` | (비어 있음) | 보스전 졸개. **비어 있으면 졸개 없음** — 졸개 없는 구역도 정상 설정이라 경고하지 않음 |
| `MinionsPerPlayer` | 3 | 플레이어 한 명에게 한 번에 소환하는 수 (= 그 플레이어에게 붙는 최대 수) |

| `MinionSpawnRadius` | 1000 | 플레이어 주변 소환 반경. 절반 안쪽은 제외, 구역 박스 밖은 쓰지 않음 |

전부 `EditAnywhere` — 구역은 레벨 배치 액터라 인스턴스마다 정한다. 스캔 주기(`ScanInterval` 0.5초)와 졸개 지점 탐색 시도 횟수(`MaxMinionSpawnLocationTries` 10)는 상수다.

## 검토했지만 채택하지 않은 것

| 안 | 이유 |
|---|---|
| 트리거 오버랩으로 인원 판정 | 리스폰마다 폰이 바뀌어 오버랩 상태를 다시 맞춰야 함 (스포너와 같은 이유) |
| 보스를 맵에 배치해 두고 등장 때 깨우기 | 잠든 상태(AI·표시·충돌)를 새로 만들어야 함. 소환하면 생성 연출·두뇌 시작이 기존 경로 |
| 구역 액터 복제 + OnRep 으로 입구 충돌 켜고 끄기 | 차단 액터 소환·파괴가 같은 결과를 복제 코드 없이 냄 |
| 대기 표시를 Client RPC 로 | UI 용 RPC 를 만들지 않는 원칙. 리스폰으로 HUD 가 새로 생기면 다시 보내야 함. 태그는 구독 때 현재 상태를 읽음 |
| 전원 진입 순간 입구 봉쇄 | 요청은 "보스 등장 = 봉쇄". 대신 카운트다운 중 이탈은 취소로 처리 |
| 보스전 중 구역 안에서 부활 | 요청은 구역 밖 부활. 그 대가로 전멸 리셋이 필요해짐 |
| 부활 시점에 보스전 여부 판정 | 전멸 리셋 뒤 부활하는 마지막 사망자들만 PlayerStart 로 감 |
| 구역이 게임모드에 부활 위치 등록·해제 | 해제 누락 여지. 사망 시점에 레벨을 훑으면 진실이 구역 단계 하나에 있음 |
| 대기 인원 표시("2/4") | 요청 없음. 필요해지면 복제 정수 하나 |
| 카운트다운을 태그만으로 + 위젯에 5초를 따로 | 같은 값이 WBP·구역 두 곳에 생김. 기간 GE 는 남은 시간을 서버가 줌 |
| 카운트다운을 Client RPC 나 GameState 종료 시각 복제로 | UI 용 복제 코드를 만들지 않는 원칙. 리스폰으로 HUD 가 새로 생기면 다시 보내야 함 |
| 보스 등장을 스캔에서 시각 비교 | 숫자가 0 이 된 뒤 최대 0.5초 늦게 등장. 1회 타이머로 GE 만료와 같은 순간에 맞춤 |
| 스캔 주기 `UPROPERTY` | 이탈 감지 지연 외에 영향이 없어 튜닝 대상이 아님 |
| 등장 카메라 전환을 클라가 스스로 (보스의 GameplayCue 로 각자 `SetViewTarget`) | 서버의 뷰 타겟과 어긋날 수 있고, 연출 끝을 각 클라가 따로 판단해야 함. 서버 전환이면 엔진 RPC 하나로 맞음 |
| 카메라를 보스 기준(큐 액터에 카메라)으로 | 구도가 방 구조에 달려 있어 벽에 박힐 수 있음. 구역이 레벨에서 잡는 편이 안전 |
| 레벨 시퀀스로 연출 | 런타임에 소환된 보스를 시퀀스에 바인딩하는 비용이 큼. 고정 카메라 + 블렌드로 시작 |
| 구역에 연출 시간 값 | 몽타주 길이와 값이 두 곳에 생김. 어빌리티 종료(태그 제거)를 기다림 |
| 연출 중 행동 차단을 게임플레이 IMC 제거로 | IMC 는 EasyGameUI 스택이 "걷기 직전 상태를 되돌리는" 방식으로 관리해, 연출이 직접 빼고 넣으면 일시정지 메뉴·레벨업 카드 창과 순서가 엉켜 메뉴 위에서 입력이 살아나거나 입력이 죽은 채 남는다 → 연출용 위젯을 스택에 올려 "Remove Gameplay IMCs" 를 선언해야 하고, 클라 신호(`SetCinematicMode` 오버라이드)·위젯 클래스 등록·WBP 가 따라온다. 입력만 막는 목적엔 GE 가 부품이 적다. **레터박스 같은 연출 화면이 필요해지면 그 위젯이 입력 차단까지 겸하도록 IMC 방식으로 옮기는 것을 검토** |
| 연출 중 공격만 차단 | 대시·점프·Sprint 는 시네마틱 모드를 거치지 않고 캐릭터를 움직임 (위 표) |
| 서버에서 `BlockAbilitiesWithTags` 직접 호출 | 소유 클라는 모르므로 예측 발동 후 서버 거부로 몽타주가 끊김 |
| 연출 중 HUD 숨김 | 요청 없음 |
| 졸개를 `ACBEnemySpawner` 로 (보스전에만 켜기) | 스포너 규칙은 팀 단위(범위 안 인원 × N, 전원 전멸 후 재소환)라 플레이어별 주기·플레이어 주변 소환과 다르다. 보스전 단계·연출을 몰라 켜고 끄는 상태도 새로 필요 |
| 졸개를 별도 액터·컴포넌트로 | 보스전 단계·연출 여부·구역 안 인원·박스 판정이 전부 구역에 있어, 밖에 두면 그것들을 공개하거나 다시 세야 함 |
| 보스 어빌리티로 졸개 소환 | 보스가 플레이어별 상태와 구역 범위를 알아야 함. "보스가 소환 동작을 한다"는 연출은 요청에 없음 |
| 졸개를 퍼셉션으로만 (플레이어를 바라보게 소환) | 다른 플레이어가 더 가깝거나 때리면 그쪽으로 가고, 숨으면 놓침 → "그 플레이어를 계속 추격" 불충족 |
| 졸개 전용 컨트롤러 서브클래스 | 지정은 몬스터 종류가 아니라 "누가 소환했나"의 문제. 서브클래스면 졸개 전용 캐릭터 BP·컨트롤러 BP 가 따로 필요하고, 같은 Rogue 를 일반 스포너와 함께 쓸 수 없음 |
| 주인이 죽으면 졸개도 사라짐 | 남은 플레이어를 노리는 것이 추가 코드 없이 나오는 동작. 사라지게 하려면 묶음 정리에서 주인 사망을 보고 파괴 |
| 졸개 최소 거리·첫 소환 지연 별도 파라미터 | 반경의 절반·재소환 지연으로 유도. 차이가 필요해지면 추가 |
| 인원 배율을 소환 직후에 적용 | 로드아웃이 아직 로드 중이면 뒤늦은 시작 GE(Instant Override)가 덮어씀. 준비 완료가 시작 GE 다음임이 보장된 지점 |
| 인원 배율을 GE 에셋 + SetByCaller 로 | 규칙이 "× 인원" 하나라 에셋·태그·프로퍼티·설정 검증만 늘어남. 다른 어트리뷰트(공격력 등)까지 인원에 맞춰야 하면 그때 GE 로 옮겨 어떤 값을 곱할지를 데이터로 |
| 인원당 증가율 파라미터 (예: 1 + 0.75 × (N−1)) | 요청은 "인원만큼"(선형). 밸런스상 필요해지면 구역 인스턴스 값 하나 |
| 보스전 중 이탈하면 체력 다시 줄이기 | 요청 없음. 체력 비율을 유지하며 줄이는 규칙이 따로 필요 |
| 기절 위젯이 `MaxStunGauge` 변경을 구독 | 최대값은 보스 준비 때 한 번만 바뀌고 그때 게이지는 0 이라 표시 차이가 없음. 다음 적립 때 새 최대값을 읽음 |

## 알려진 한계

- **보스전 중 부활해 밖에 있는 플레이어에게는 아무 표시가 없다.** 입구가 열릴 때까지 기다린다.
- **보스 구역이 동시에 둘 이상 보스전 중이면** 부활 위치는 레벨에서 먼저 찾은 구역을 쓴다. 지금은 구역이 하나라 다루지 않는다.
- **전멸 리셋 때 보스가 연출 없이 사라진다** (위 "전멸 리셋").
- **클라이언트가 보스 에셋을 처음 디스크에서 읽느라 늦으면 그 화면에서만 등장 몽타주가 빠질 수 있다.** 몽타주 큐는 받는 순간 재생을 요청하는데(`UCBGCN_PlayAction`), 그때 보스가 아직 준비 전이면 몽타주 데이터가 없다. 카메라는 정상이고 보스만 서 있다. PIE 는 에셋이 메모리에 있어 재현되지 않는다 — 패키징 빌드에서 확인하고, 실제로 빠지면 구역이 `BeginPlay`(모든 머신)에서 보스 로드아웃을 미리 로드한다.
- **연출 시작 순간 이미 진행 중이던 행동은 끊지 않는다.** 차단은 새 발동만 막으므로, 공격 몽타주 도중에 보스가 나오면 그 공격은 끝까지 나간다(카메라는 이미 넘어가 있음).
- 스폰 높이는 CDO 캡슐 기준이라, 로드아웃 바디 셋업이 캡슐을 키우는 캐릭터는 첫 프레임에 살짝 묻힐 수 있다(이동 시 엔진이 밀어냄). 스포너와 같은 한계.
- **졸개 주인이 죽으면 남은 졸개가 다른 플레이어에게 간다.** 그 사이 다른 플레이어에게는 자기 졸개 + 주인 잃은 졸개가 함께 붙는다.
- **졸개 소환 지점을 못 찾으면 그 마리만 건너뛰어** 묶음이 3마리보다 적을 수 있다(전부 잡아야 다음 소환).
- **로딩이 끝나지 않은 플레이어**는 seamless travel 중 서버 컨트롤러 목록에 아직 없을 수 있다. 구역이 시작 지점에서 멀어 걸어가는 동안 로딩이 끝나므로 실제로는 생기지 않는다.
- **보스전 중 누가 나가도 보스 내구도는 그대로다.** 남은 인원이 시작 인원 기준의 보스를 상대한다.

## 검증 (2인 리슨 서버)

1. 호스트만 구역에 들어가면 호스트 화면에만 "대기 중"이 뜨고 보스는 나오지 않는다
2. 클라도 들어가면 둘 다 대기 문구가 카운트다운(5 → 0)으로 바뀌고, **0 이 되는 순간** 보스가 나타나며 입구가 막힌다. 두 화면의 숫자가 거의 같다. **클라에서 벽으로 달려도 튕기지 않고 막힌다**
3. 카운트다운 중 한 명이 나가면 양쪽 카운트다운이 내려가고 안에 남은 사람에게 다시 "대기 중". 다시 들어오면 5초를 처음부터 센다
4. 대기 중 사망 → 표시가 꺼지고 PlayerStart 에서 부활
5. 보스전 중 한 명 사망 → 5초 뒤 `RespawnPoint` 에서 부활, 입구가 막혀 들어갈 수 없음
6. 보스 처치 → 입구 차단 액터가 양쪽 화면에서 바로 사라지고, 보스가 소멸 연출로 사라진 뒤 양쪽에 클리어 위젯이 뜸 (이후 흐름은 → [GameFlow.md](../Flow/GameFlow.md) "매치 종료" 검증)
7. 보스전 중 전원 사망 → 보스·보스 바가 사라지고 입구가 열림, 전원 `RespawnPoint` 에서 부활. 다시 전원 진입 → 5초 뒤 새 보스
8. 카운트다운 중 레벨업 → 정지 동안 화면 숫자와 보스 등장이 함께 멈췄다가 재개 후 이어짐
9. `CountdownEffectClass` 를 비우면 경고 로그가 남고, 숫자 없이 5초 뒤 보스가 나온다
10. 보스가 나타나는 순간 **호스트·클라 모두** 카메라가 `IntroCamera` 로 블렌드되고 이동·시점이 막힌다. 보스는 디졸브로 나타나며 등장 몽타주를 재생하고, 그동안 움직이거나 공격하지 않는다
    - 연출 중 **클라에서** 공격·대시·점프·버스트·무기 장착 키를 눌러도 아무 동작이 없다 — 몽타주가 시작됐다 끊기지도 않는다(예측 발동 자체가 막힘). `showdebug abilitysystem` 으로 차단 GE 확인, 연출이 끝나면 사라짐
11. 등장 몽타주가 블렌드 아웃되는 순간 양쪽 카메라가 자기 캐릭터로 돌아오고 조작이 풀리며, 보스가 싸움을 시작한다
12. 로드아웃에서 `GA_Boss_Intro` 를 빼면 경고 로그가 남고 카메라가 곧바로 돌아온다 (묶인 채 남지 않음)
13. 연출이 끝나고 `MinionRespawnDelay` 뒤 **호스트·클라 각자의 주변**에 졸개가 3마리씩 디졸브로 나타나 자기 플레이어를 바라보고 쫓는다. 연출 중에는 나오지 않는다
14. 졸개는 다른 플레이어가 더 가까이 있거나 때려도, 기둥 뒤로 숨어도 자기 플레이어만 쫓는다
15. 호스트의 졸개 3마리를 다 잡으면 `MinionRespawnDelay` 뒤 **호스트 주변에만** 다시 3마리. 클라의 졸개가 남아 있는 동안 클라 쪽은 새로 나오지 않는다
16. 졸개 주인이 죽으면 남은 졸개가 다른 플레이어를 노린다. 주인은 구역 밖에서 부활하고 그 몫은 새로 나오지 않는다
17. 보스 처치 → 남은 졸개가 사망 몽타주와 소멸 연출로 쓰러진다. 보스전 중 전멸 → 졸개가 보스와 함께 사라지고, 다시 들어오면 처음부터
18. 졸개가 입구 벽 너머(구역 밖)에 나타나지 않는다
19. 보스가 나오면 서버 로그에 `보스 내구도 x2` 가 남고, 보스 바의 체력이 혼자일 때의 두 배에서 가득 찬 채 시작한다(`showdebug abilitysystem` 으로 `MaxHealth`·`CurrentHealth`·`MaxStunGauge` = 혼자일 때 × 2 확인). 클라 화면 보스 바도 같은 값
20. 기절은 혼자일 때의 두 배를 맞아야 걸리고, 보스 바 기절 게이지가 그 기준으로 찬다 (→ [Stun.md](Stun.md) 검증)
21. 혼자 보스전을 하면 로그가 없고 값이 로드아웃 데이터 그대로다
22. 보스전 중 클라가 접속을 끊어도 보스 값은 그대로다. 그 뒤 호스트가 전멸 리셋을 겪고 다시 들어가면 새 보스는 ×1 로 나온다
