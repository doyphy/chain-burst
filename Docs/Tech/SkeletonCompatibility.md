# 스켈레톤 호환성 — 새 메시를 애니메이션에 맞추기

> 캐릭터 역할(Chaser / Rogue / Outlaw)마다 고유한 애니메이션 팩과 스켈레톤을 쓴다.
> 그 캐릭터에 새 메시를 적용할 때, 메시가 **해당 애니메이션 스켈레톤**과 호환되는지 검증하고 어긋난 부분을 메우는 절차.

**전제: 애니메이션은 스켈레톤에 하드 참조로 묶여 있다.**
- `UAnimSequence`는 `Skeleton` 포인터를 하드 참조로 보유하고, 본 트랙은 그 스켈레톤의 본 트리를 통해 **이름으로 바인딩**된다.
- 따라서 "새 메시를 붙인다"는 것은 곧 **"그 메시의 본 구성이 애니메이션 스켈레톤과 맞는가"** 의 문제다.
- 프로젝트에 기준 스켈레톤이 하나만 있는 게 아니다. **캐릭터마다 애니메이션 팩이 다르면 스켈레톤도 다르고, 이 절차는 캐릭터마다 반복된다.**

**핵심: 런타임 본은 스켈레톤 에셋이 아니라 메시의 Reference Skeleton에서 온다.**
- `USkeletalMeshComponent`의 본 컨테이너는 `SkeletalMesh->GetRefSkeleton()`으로 만들어진다.
- 스켈레톤 에셋(`USkeleton`)의 BoneTree는 그 스켈레톤을 쓰는 **모든 메시의 본 합집합**이다. 개별 메시는 그 부분집합일 수 있고, 부분집합이어도 정상 동작한다.
- **스켈레톤 에셋에 있는 본이라도 메시에 없으면 런타임에 존재하지 않는다.** 호환 스켈레톤(Compatible Skeletons) 설정으로는 없는 본이 생기지 않는다. 그 본의 애니메이션 트랙은 **경고 없이 버려진다.**
- 방향은 한쪽뿐이다. 메시에 본을 추가하면 스켈레톤 BoneTree로 자동 병합되지만, 스켈레톤에 본을 추가한다고 메시에 생기지는 않는다. (예외: Virtual Bone은 스켈레톤에 추가되어 모든 메시에 나타나지만, 두 본의 상대 트랜스폼으로 **계산되는** 본이라 애니메이션 트랙을 받을 수 없다.)

## 두 층위 — 분리해서 판단한다

| 층위 | 질문 | 어긋나면 |
|---|---|---|
| **1. 호환 가능한가** | 공통 본의 **이름·부모·로컬 축**이 일치하는가 | 포즈가 깨진다. 호환 스켈레톤 불가 |
| **2. 기능이 온전한가** | **애니메이션이 구동하는 커스텀 본**이 메시에 있는가 | 몸은 정상인데 그 본에 의존하는 기능(무기 부착 등)만 죽는다 |

층위 1만 보고 넘어가면 "애니메이션은 잘 나오는데 검이 손에서 떨어져 있는" 상태가 된다. 두 개를 따로 확인할 것.

**"기본 뼈대"가 아니라 "애니메이션이 구동하는 본"이 기준이다.** 치마·머리카락처럼 애니메이션이 안 건드리는 본은 없어도 무방하지만, 무기 본이나 IK 본은 겉보기에 세부 본이어도 없으면 기능이 죽는다.

## 판별 — UE4 계열 / UE5 계열

에픽 마네킹 계열은 UE4↔UE5 사이에 계층이 바뀌었다. **이 세 본의 유무로 즉시 갈린다.**

| 본 | UE5 | UE4 |
|---|---|---|
| `spine_05` | ✅ (spine 5개) | ❌ (spine 3개) |
| `neck_02` | ✅ (neck 2개) | ❌ (neck 1개) |
| `*_metacarpal_*` | ✅ | ❌ (손가락이 `hand_*`에 직접) |

셋 다 없으면 UE4 계열이고, 그 경우 UE5 애니메이션과는 **부모 불일치가 10개 이상 대량 발생**한다. 상점 페이지의 갤러리 이미지에 스켈레톤 트리가 보이면 구매 전에도 판별할 수 있다.

에셋 팩 설명의 `"Fully compatible with UE5 skeleton"` 같은 문구는 **"리타게팅하면 쓸 수 있다"** 는 뜻인 경우가 많다. `"rigged at UE4 skeleton"` 처럼 구체적인 문장이 있으면 그쪽을 믿는다.

## 진단 — `Tools/skeleton_diff.py`

메시를 임포트한 직후, **환불 가능 기간 안에** 돌린다.

1. 콘텐츠 브라우저에서 검사할 스켈레탈 메시를 선택
2. 스크립트의 `A` 상수를 **그 캐릭터의 애니메이션 스켈레톤이 쓰는 메시** 경로로 지정
3. `Tools > Execute Python Script` 또는 파이썬 콘솔에서 `exec(open(...).read())`
4. Output Log(`LogPython`)에서 결과 확인

| 결과 | 판정 |
|---|---|
| 부모 불일치 0, `[!]` 없음 | 바로 사용 |
| 부모 불일치 0, `[!]` 있음 | 사용 가능. **커스텀 본 추가 숙제** (아래 절차) |
| 부모 불일치 있음 | 호환 스켈레톤 불가. IK 리타게터 검토 |

`[!]` 는 이름에 `weapon`, `ik_`, `holder`, `prop`, `attach` 가 들어간 본이다. 게임플레이가 의존할 가능성이 높다는 휴리스틱이며 확정 판정은 아니다.

레퍼런스 포즈 **로컬 회전 차이**도 함께 본다(현재 스크립트 미구현, MCP로 측정 가능).

| 차이 | 판단 |
|---|---|
| 1~5° | 안전. 체형·포즈 차이 수준 |
| 10~20° | 손목·쇄골 등 국소 부위면 감수 가능 |
| 수십~180° | 축 규약이 다름. 호환 스켈레톤 불가 |

## 판정별 대응

| 방법 | 언제 | 비용 |
|---|---|---|
| **Compatible Skeletons** | 공통 본의 이름·계층·축이 일치 | 없음. 에셋 복제 없이 원본 애니메이션을 그대로 재생 |
| **IK Retargeter** | 이름·계층·축이 다르거나 체형 차이가 큼 | 타겟 스켈레톤용 **애님 에셋이 전부 복제 생성**. AnimBP도 별도 필요 |
| **메시에 본 추가** | 애니메이션이 구동하는 커스텀 본이 메시에 없음 | 에디터 수동 작업. **FBX 재임포트 시 소실** |

앞의 둘은 "있는 본을 어떻게 연결할까", 세 번째는 "없는 본을 어떻게 만들까"를 다룬다. **층위가 다르므로 대체 관계가 아니다.** 부모 불일치가 없더라도 커스텀 본이 빠졌으면 세 번째가 따로 필요하다.

## 대안 — 교체하지 않고 덧입히기 (리더 포즈)

지금까지는 **메시를 교체**하는 전제였다. 기존 메시를 리더로 그대로 두고 새 메시를 **팔로워로 덧입히면**(`USkeletalMeshComponent::SetLeaderPoseComponent`) 위의 두 층위가 **둘 다 사라진다.**

| 층위 | 교체 방식 | 리더 포즈 방식 |
|---|---|---|
| 1. 호환 가능한가 | Compatible Skeletons 또는 IK 리타게터 | **불필요** — 애니메이션은 원래 스켈레톤에서 그대로 재생 |
| 2. 커스텀 본 | 새 메시에 수동 추가 (재임포트 시 소실) | **불필요** — 리더가 계속 보유 |

- 팔로워는 자기 애님BP를 돌리지 않고 리더의 컴포넌트 공간 트랜스폼을 **본 이름으로** 받는다. 팔로워에 없는 본은 안 쓰일 뿐이고, 리더에만 있는 본(`weapon_r1`·`ik_*`)은 리더가 계속 구동한다.
- **팔로워는 전부 리더에 평면 부착**한다. 팔로워 밑에 팔로워를 두는 연쇄는 엔진이 지원하지 않아 갱신이 밀리거나 누락된다. 어태치 계층과 리더 포즈 지정은 별개 개념이다.
- 리더를 숨길 때는 **`VisibilityBasedAnimTickOption = AlwaysTickPoseAndRefreshBones`를 함께 설정**한다. 숨긴 메시는 기본적으로 애님 틱을 건너뛰므로 팔로워 전체가 레퍼런스 포즈로 얼어붙는다.

**대신 스키닝은 리더 골격을 따른다.** 스킨 행렬 = `리더의 컴포넌트공간 트랜스폼 × 팔로워의 바인드포즈 역행렬` 이므로:

| 차이 | 결과 |
|---|---|
| 레퍼런스 포즈 동일 | 스킨 행렬 = 항등. 팔로워가 제작된 그대로 렌더 |
| 본 길이가 다름 | 그 본에 웨이트된 정점이 밀림 → 관절부에서 **늘어남**(체형에 맞춰 재단되는 게 아님) |
| 본 로컬 축이 다름 | 그 부위가 돌아감 |
| **몸 두께·볼륨이 다름** | **보정 불가.** 본이 아니라 메시 형상이라 옷 안에서 몸이 관통한다 |

따라서 **팔로워는 리더와 같은 체형 기준으로 제작된 것**이어야 한다. 본 이름이 100% 일치하고 부모 불일치가 0이어도 볼륨 차이는 해결되지 않는다.

구현: `UCBModularMeshComponent` → [Components.md](Components.md)

## Compatible Skeletons 등록

메시 쪽 스켈레톤 에셋에서 설정한다.

- `CompatibleSkeletons` 에 **애니메이션이 묶여 있는 스켈레톤**을 추가한다. 프로퍼티 설명대로 **양방향이 아니다** — "이 스켈레톤이 배열 안 스켈레톤의 애니메이션 데이터를 쓸 수 있다"는 뜻이므로, 소비하는 쪽(새 메시의 스켈레톤)에 등록한다.
- `bUseRetargetModesFromCompatibleSkeleton = true` 로 두면 본별 리타게팅 모드를 소스 스켈레톤에서 물려받는다. 새로 추가한 본의 모드도 자동으로 따라온다.

**함정 — Compatible Skeletons는 구조를 검증하지 않는 화이트리스트다.** UE4에서 스켈레톤 GUID로 막던 안전장치를 "내가 책임진다"고 끄는 것에 가깝다. 부모가 다른 본이 있어도 **에러 없이 통과**하고, 로컬 트랜스폼이 잘못된 부모 공간에 적용되어 조용히 망가진다. 그래서 등록 전에 진단이 필요하다.

이 프로퍼티들은 Persona의 Details 패널에 나오지 않는다(선택 항목만 보여주는 패널이다). 콘텐츠 브라우저에서 스켈레톤 에셋 우클릭 → **Asset Actions → Bulk Edit via Property Matrix** 로 편집한다.

## 애니메이션이 구동하는 커스텀 본 추가

애니메이션 팩이 자체 목적으로 추가한 본(무기 본 등)이 새 메시에 없을 때의 절차.

1. **(필수)** 동일한 이름의 본을 **메시의 Reference Skeleton**에 추가한다. UE 5.5+ 스켈레탈 메시 에디터의 Skeleton Editing 툴(스켈레톤 트리에서 본 우클릭 → Add Bone). 스킨 웨이트 없는 헬퍼 본이라 리스키닝은 불필요하다.
2. **(필수)** 부모 본을 원본과 동일하게 지정한다. 부모가 다르면 로컬 트랜스폼이 잘못된 공간에 적용되어 조용히 망가진다.
3. **(권장)** 레퍼런스 포즈 로컬 트랜스폼도 원본과 동일하게 입력한다.
4. **(권장)** 리타게팅 모드를 확인한다. 무기 본처럼 **절대 오프셋이 유지돼야 하는 본은 `Animation`**. 3번을 정확히 했다면 다른 모드도 대개 동작하지만 `Animation`이 가장 안전하다.
5. 부착용 소켓의 **부모 본**을 그 본으로 지정한다.

추가한 본은 스켈레톤 에셋 BoneTree로 자동 병합되므로 스켈레톤 쪽 작업은 없다.

**함정 — 에디터에서 수동 추가한 본은 FBX 재임포트 시 사라진다.** 원본 FBX에 없기 때문이다. 팩을 업데이트하거나 메시를 다시 뽑으면 이 절차를 다시 밟아야 한다. 근본 해결은 DCC에서 FBX 자체에 본을 넣는 것.

### 사례 — Chaser / Sword 팩의 `weapon_r1`

`SK_Mannequin_Sword`(163본)에서 검을 구동하는 본. 에픽 기본 본이 아니라 **소드 애니메이션 팩 제작자가 끝에 추가한 본**이다(`weapon_r1` 인덱스 161, `sword_holder` 162). 에픽 원본 `weapon_r`(88), `weapon_l`(42)과는 별개.

| 항목 | 값 |
|---|---|
| 부모 본 | `hand_r` |
| Location | `(-9.008535, 2.976805, 0.588345)` |
| Rotation | `Pitch 0, Yaw -180, Roll 180` (Y축 180° 회전) |
| Scale | `(1, 1, 1)` |
| 리타게팅 모드 | `Animation` |
| 소켓 | `weapon_r1Socket`, 부모 본 `weapon_r1`, 트랜스폼 **아이덴티티** |

소켓 이름 `weapon_r1Socket`은 `DA_WeaponSocketData`의 `Sword → CombatSocket` 및 `BP_Weapon_Chaser_Sword.CombatSocketOverride`와 맞춘 값이다. → [Combat.md](Combat.md)

## 리타게팅 모드 — 이동값에만 적용된다

**회전과 스케일은 모드와 무관하게 항상 애니메이션 값을 그대로 쓴다.** 모드가 관여하는 것은 이동값뿐이다.

| 모드 | 이동값 처리 |
|---|---|
| `Animation` | 애니메이션 값 그대로 (무기 본처럼 절대 오프셋이 필요한 경우) |
| `AnimationScaled` | 애니메이션 값 × (타겟 본 길이 / 소스 본 길이). 체형 차이를 흡수 |
| `Skeleton` | 애니메이션 무시, 타겟 레퍼런스 포즈 값 사용 |

**체형(본 길이) 차이는 `AnimationScaled`가 흡수한다.** 실측상 본 길이가 수 % 달라도 문제되지 않았다. 반면 **본의 로컬 축 방향이 다르면 회전이 그대로 복사되어 포즈가 뒤틀린다** — 이건 어떤 모드로도 해결되지 않는다.

## 소켓

- 소켓 이름은 **부착 코드 기준**이다. 애니메이션과 무관하다.
- 소켓에서 중요한 것은 **부모 본**이다. 소켓은 부모 본의 트랜스폼을 따라가므로, 애니메이션이 구동하는 본에 붙으면 함께 움직인다.
- 스켈레톤 소켓과 메시 소켓은 **별개의 배열**이다. 이름이 겹치면 **메시 소켓이 우선**한다. 스켈레톤 소켓은 그 스켈레톤을 쓰는 모든 메시에서 조회되지만, **부모 본이 그 메시에 존재해야** 해석된다.

## 함정 모음

- **조용한 실패가 기본이다.** 본이 없어서 트랙이 버려질 때도, 부모가 달라서 잘못된 공간에 적용될 때도 에러나 경고가 없다. 진단 없이 눈으로 찾으려 하지 말 것.
- **"UE5 호환" 표기는 층위 1만 보장한다.** 팩이 추가한 커스텀 본까지 보장하지 않는다.
- **고아 본**이 있을 수 있다. 본 이름은 다 맞는데 부모 링크가 없는 경우(Robot3에서 보정 본 72개 관측). 코어 골격이 정상이면 대개 무해하나, 그 본에 스킨 웨이트가 걸려 있으면 메시가 찢어질 수 있다. 실제 재생으로 확인할 것.
- **부모 링크가 없는 본은 `get_bone_parent`가 루트와 동일하게 빈 값을 반환한다.** 진단 시 루트와 구분할 것.
