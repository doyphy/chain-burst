# 코딩 컨벤션

> ChainBurst 코드를 작성할 때 지키는 주석·구조·설계 규칙 모음.

## 1. 주석 스타일 — 헤더 `/** */`, 구현부 `//`

- **헤더 파일(.h)**: `/** */` — 코드 한 줄 설명이 아니라 **전체 기능·분류 등 큰 범위**를 가리킬 때. 인터페이스/분류를 큰 단위로 드러내는 곳이라 블록 주석이 어울린다.
- **구현 파일(.cpp)**: `//` — 코드의 기능·설명 등 **상대적으로 작은 범위**를 가리킬 때. 세부 로직을 짧게 짚는 곳이라 라인 주석이 어울린다.

즉, 헤더의 `#pragma region` 요약·클래스/함수 분류 주석은 `/** */`로, 구현부의 로직 설명 주석은 `//`로 쓴다.

### 종결 어미는 명사형 (`~함.`)

주석 문장은 **`~한다.` / `~된다.`가 아니라 `~함.` / `~됨.`** 으로 짧게 끝낸다. 헤더·구현부 모두 동일.

```cpp
// ✅ 슬롯을 배열 인덱스로 쓰므로 항상 슬롯 개수만큼 확보함.
// ❌ 슬롯을 배열 인덱스로 쓰므로 항상 슬롯 개수만큼 확보한다.
```

금지·주의를 나타내는 문장은 자연스러운 형태를 우선한다 (`~하지 말 것.`, `~ 금지.`).

**Why:** 주석은 설명문이 아니라 표식이다. 종결을 줄이면 한 줄이 짧아지고 코드 옆에서 눈에 덜 걸린다. (`Docs/*.md` 본문은 산문이므로 이 규칙 대상이 아니다)

## 2. `#pragma region`으로 역할별 구분

클래스가 커지면서 **여러 역할이나 기능을 담당하게 되면 `#pragma region`으로 멤버 함수와 멤버 변수를 기능/역할별로 구분**한다.

- 각 region은 하나의 기능/역할 단위 (예: `CBCombatComponent` → Core / Weapon / CombatState / WeaponTrace / Combo).
- region 안에서는 필요한 만큼 `public/protected/private`를 다시 나눈다.
- region 요약 주석은 헤더이므로 `/** */`로 쓴다 (§1).
- **단일 책임의 작은 클래스는 굳이 나누지 않는다.** 역할이 둘 이상으로 뚜렷해질 때 분리한다.

**Why:** 큰 헤더에서 IDE 폴딩으로 탐색이 쉬워지고, 어떤 기능의 멤버인지 경계가 분명해진다. 프로젝트에 이미 `CBBaseCharacter.h`(`#pragma region Components`) 등에서 쓰는 스타일이라 일관됨.

## 3. 디폴트 매개변수는 구현부에도 `/* = 값 */` 주석

디폴트 매개변수가 있는 함수는, 구현 파일(.cpp)의 함수 정의문에도 **`/* = 값 */` 주석으로 기본값을 표시**한다. (C++ 문법상 구현문엔 실제 기본값을 못 쓰므로 주석으로 대신)

```cpp
bool UCBActionComponent::RequestPlayMontage(const FGameplayTag& InActionTag, int32 InIndex /* = 0 */)
```

**Why:** 구현부만 봐도 어떤 매개변수가 기본값을 갖고 그 값이 무엇인지 바로 알 수 있어, 헤더를 오가지 않아도 된다.

## 4. 클래스 주석 동기화

클래스 선언문 위에는 **그 클래스의 역할과 어떤 기능을 하는지 간략히 설명하는 주석**을 둔다 (헤더이므로 `/** */`, §1). **클래스의 기능이 수정·추가되면 이 주석 내용도 함께 편집**한다.

- 함수/멤버 추가·제거로 클래스 책임이 바뀌면 선언문 위 주석을 같이 수정.
- 클래스뿐 아니라 그 안의 함수/멤버 주석도 기능이 바뀌면 함께 갱신 (예: 타이머 제거 시 "타이머도 취소" 문구 삭제).

**Why:** 클래스 상단 주석이 실제 기능과 어긋나면(=stale) 코드를 오해하게 됨.

## 5. 컴포넌트 결합 최소화 (독립적 설계 선호)

**컴포넌트끼리 서로 엮이는 구조를 지양한다.** 컴포넌트 하나가 사라지거나 문제가 생겨도 다른 컴포넌트는 정상 동작하는 독립적 설계를 선호.

- **컴포넌트는 형제 컴포넌트를 직접 참조/호출하지 않는다.** 필요한 데이터는 **주입(파라미터/세터)** 받는다 (fetch 하지 말고 inject).
- **오케스트레이터가 배선**한다: 오너(캐릭터)나 GAS 어빌리티가 참조를 쥐고 컴포넌트를 조율. 컴포넌트끼리는 서로 모른다. (어빌리티가 ActorInfo로 여러 컴포넌트를 조율하는 건 GAS 본연의 역할이라 OK)
- 부득이 교차 참조가 필요하면 **인터페이스 경유 + null 체크로 우아한 저하** (없어도 자기 핵심 기능은 동작).
- 컴포넌트 간 알림은 **이벤트/델리게이트**로 느슨하게.

**단, 절대 규칙은 아님:** 비용을 따져 서로 엮는 게 더 효율적이거나 유지보수가 더 낫다고 판단되면 결합 구조도 채택 가능. 트레이드오프를 제시하고 정할 것.

**예:** 콤보 최대치를 `CBCombatComponent`가 `ActionComponent`에서 fetch하지 말고, 오케스트레이터(어빌리티)가 몽타주 개수를 구해 `AdvanceCombo(Tag, MaxCount)`로 주입. (→ [Combat.md](Combat.md), [Montage.md](Montage.md))
